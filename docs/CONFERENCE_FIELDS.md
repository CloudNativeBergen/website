# Conference fields

Every field of the Sanity `conference` document type, mapped to one group.
Summary and phasing: [Data ownership](./DATA_OWNERSHIP.md#conference-fields-inventory-and-phasing).

- **A**: already in D1. The column is named.
- **B**: a conference setting that should move to D1. The column or table is a proposal.
- **C**: editorial content that stays in Sanity.

How fields are counted: one row per leaf field. Nested object fields are rows
(`theme.primaryColor`); the 8 container objects (`theme`, `ticketTargets`,
`ticketCustomization`, `speakerInfo`, `speakerInfo.dinner`,
`speakerInfo.onsiteContact`, `sponsorshipCustomization`, `agentConfig`) are
not. An array is one row, with its item shape in the type column;
`homepageSections` (13 block types) is one row. Source:
`sanity/schemaTypes/conference.ts`, cross-checked against
`sanity/schema-shape.baseline.json`, which lacks four additive fields
(`cateringInfo`, `afterpartyInfo`, `speakerSlackInviteUrl`,
`sponsorRenewalLeadMonths`).

Write path: **patch** means the field is in a `src/server/schemas/conference.ts`
input and is written by `applyConferencePatch` in
`src/server/routers/conference.ts`. **Studio/other** means Sanity Studio or
another router or job (named in the notes where known). "Content subgraph"
means `services/content` serves the field today. Consumers are the main
directories under `src/`, not a complete list.
