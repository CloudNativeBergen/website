# Research: storing Wall Post photos and delivering them live

Ticket: [#1476](https://github.com/CloudNativeBergen/website/issues/1476) (map [#1474](https://github.com/CloudNativeBergen/website/issues/1474)). Researched 2026-10-23.
This file records facts and costed options only. It decides nothing.

Labels:

- **VERIFIED**: read in a primary source (Vercel, Sanity, WebKit or MDN docs; the installed SDK or Next.js docs; our code; production Sanity read-only).
- **OBSERVED**: tried against a live endpoint today, not documented anywhere.
- **ESTIMATE**: arithmetic on stated assumptions.
- **NOT FOUND**: looked for in the primary source and not there.

The reference edition in every estimate: a few hundred attendees, **100–1,000 Wall Posts**, 2 days, **1–4 venue screens** and about **300 phones** opening the Wall page at some point.

## Summary

1. **The 4.5 MB limit is real and client uploads are the only way round it.** "The maximum payload size for the request body or the response body of a Vercel Function is 4.5 MB" (VERIFIED). A browser can upload past it directly to Vercel Blob with a token our server mints (`handleUpload`), which the repo already does twice. Sanity has no equivalent: an asset upload needs a write token, and Sanity's own docs say not to put one in a browser. So "Sanity asset upload with a server-minted token" means a server route, which is inside the 4.5 MB limit, so it only works for photos already resized on the phone.
2. **A Sanity asset can never be the pending copy.** "Assets stored in a dataset are public on the asset CDN, even when the dataset is private… Anyone who has the URL can still fetch the file" (VERIFIED). The URL is unguessable (content hash), but the ticket's rule is "never publicly fetchable by URL", and that is exactly what a Sanity asset is. Per-asset visibility exists only in the Enterprise Media Library.
3. **Vercel Blob now has private stores, and that is the one store on the stack that satisfies the rule.** A private blob's URL "is not publicly accessible"; it is read with `get()` in a route, or through a signed URL valid at most 7 days (VERIFIED). The access mode is fixed per store, so approval means copying bytes from the private store to a public one (or to Sanity): the bytes pass through a function once. The repo's `@vercel/blob` 2.8.0 is past the 2.3 minimum.
4. **Resizing on the phone solves three problems at once**: it brings a 3–12 MB photo to about 0.3–1 MB (ESTIMATE), it drops EXIF including GPS (a canvas holds pixels only), and it turns HEIC into JPEG or WebP before anything on our side has to decode it. Neither Sanity's image pipeline nor Vercel Image Optimization transforms HEIF (VERIFIED). The catch is the iOS canvas limit MDN still records as 4,096×4,096: a 12 MP photo fits, a 24 or 48 MP one does not without decode-time downscaling (`createImageBitmap` with `resizeWidth`).
5. **Live delivery: the cheap shape is "poll our cache, expire the cache on approval".** A `'use cache: remote'` list tagged per wall, expired with `updateTag` on approval, costs about one Sanity read per approval plus background refreshes: **about 1–4k live reads per edition** (ESTIMATE), whatever the poll interval. The same screens polling Sanity directly every 5 s cost about 58k reads per edition from the screens alone (23% of the monthly quota). Sanity's Live Content API works token-less in a browser for published content on a private dataset (VERIFIED), but Growth allows **1,000 live connections per dataset** and refuses the rest with `goaway`, and the tenant's origin must be on the project's CORS list. SSE and WebSockets (public beta since June 2026) both run on Vercel Functions but close at `maxDuration` (800 s on Pro) and bill memory while idle.
6. **Volume is small.** Resized, an edition is 0.05–1 GB of photos, 100–1,000 Wall Post documents and a few GB of delivery. Sanity's Growth plan includes 100 GB of assets and 100 GB of bandwidth a month; asset documents do not count toward the document quota (VERIFIED). Blob storage is $0.023 per GB-month in arn1 (VERIFIED).
7. **No new subprocessor for Blob or Sanity.** Vercel is already in `src/lib/legal/subprocessors.ts` with "file storage for uploaded attachments", and Blob "leverages Amazon S3" under Vercel's own AWS subprocessor entry (VERIFIED). A store can be created in an EU region (arn1 or fra1 have Blob prices). A pub/sub or realtime vendor (Pusher, Ably, Upstash) would be a new processor.

### 1.2 What the repo already does

VERIFIED from the code:

- **Two-tier Blob upload** exists for proposal attachments (`src/app/api/upload/proposal-attachment/route.ts`, `src/components/proposal/AttachmentManager.tsx`) and for marketing assets (`src/app/api/admin/marketing-assets/upload-token/route.ts`, `src/components/admin/marketing/assets/upload.ts`). The browser calls `upload()` from `@vercel/blob/client`, the route's `onBeforeGenerateToken` authorizes the caller and returns `allowedContentTypes`, `maximumSizeInBytes`, `addRandomSuffix: true` and a `validUntil` (1 h for marketing assets). Both routes **require a signed-in user**; neither is a precedent for an anonymous caller.
- **The move to Sanity** (`src/lib/marketing-asset/move.ts`, `sanity-upload.ts`) refuses any URL not on the Blob store's own host and prefix, sniffs type and size from the bytes, streams the body to `POST /assets/images/<dataset>` with `duplex: 'half'` under a 45 s deadline, then deletes the blob. The marketing-assets route runs with `maxDuration = 300`.
- **The orphan sweeper** (`src/app/api/cron/cleanup-orphaned-blobs/route.ts`, daily 03:00) lists the `proposal-` and marketing-asset prefixes and deletes blobs older than 24 h. A new prefix is one array entry.
- **Client-side resize before upload** exists in `src/components/admin/gallery/ImageUploadZone.tsx` (draw to a canvas, `canvas.toBlob`, keep the original `file.type`).
- **Public unauthenticated writes** exist in `volunteer.create` (`src/server/routers/volunteer.ts`, Sanity write, de-duplicated by email) and the Feedback form (`src/app/(public)/f/[code]/actions.ts`, Server Actions, HMAC device cookie in `src/lib/feedback/device.ts`, **no IP rate limit** by decision in the speaker-feedback spec because a shared venue IP behind one bucket refused most legitimate keynote feedback in the #1416 model). Neither takes a file.
- **The token binds the pathname.** `handleUpload` passes `pathname`, the content types, the size cap and `validUntil` into `generateClientTokenFromReadWriteToken`, which HMAC-signs that payload with the store's read-write token (`node_modules/@vercel/blob/dist/client.js` lines 271–283 and 454–494, v2.8.0). The Vercel docs state this for signed tokens but not for client tokens; the SDK source does.

### 1.4 Does Sanity offer a scoped upload token?

No. VERIFIED from Sanity's docs:

- "All requests must be authenticated… Uploading requires permission to create documents in the dataset" ([http-reference/assets](https://www.sanity.io/docs/http-reference/assets)). A 403 means "The request has no token, or the token lacks the `create` permission".
- The browser alternative Sanity offers is a **logged-in Sanity user's session** (`withCredentials: true`, origin on the CORS list with credentials enabled), which anonymous attendees do not have ([js-client-assets](https://www.sanity.io/docs/apis-and-sdks/js-client-assets)).
- Tokens can carry an expiry since June 2026 ("30-, 60-, or 90-day presets, or set a custom date", [http-auth](https://www.sanity.io/docs/content-lake/http-auth)), but a per-upload, single-use or signed upload token is NOT FOUND. "Custom roles are available for Enterprise customers" ([roles](https://www.sanity.io/docs/user-guides/roles)); on Growth the narrowest writing role is Contributor, with write access to drafts in all datasets.
- The Sanity MCP server's `dataset_assets_upload_from_file` tool does "Prepare a one-use URL for uploading an image or file up to 50 MiB", but it is OAuth-authenticated and a REST equivalent is NOT FOUND, so it is not an app API.
- CORS on `api.sanity.io` applies to uploads like any other browser request, is browser-only ("does not apply when requesting from e.g. Node.js or `curl`"), and does nothing to protect a token that has reached a browser ([browser-security-and-cors](https://www.sanity.io/docs/content-lake/browser-security-and-cors), [cors](https://www.sanity.io/docs/content-lake/cors)).

So a server-minted Sanity upload token does not exist on our plan; the server itself uploads, after the body has crossed the 4.5 MB line.

## 2. Filters baked in on the phone

- **Where the pixels come from.** The photo is a local `File`, so no CORS applies to the upload-time filter. The Sanity CDN CORS problem only bites when editing an image that is already stored: the asset CDN returned `403 {"message":"CORS Origin not allowed"}` for an unlisted `Origin` (OBSERVED 2026-10-23 with curl against a Sanity docs image, matching the Studio video finding in `docs/MARKETING_STUDIO_VIDEO_SPEC.md` §6 from 2026-09-22). A plain `<img>` sends no `Origin` and loads; `fetch()`, `crossorigin` images and canvas reads from a tenant domain fail. Re-editing a stored Wall Post would therefore go through the same-origin `/api/proxy-image` pattern (`src/app/api/proxy-image/route.ts`, currently sign-in only).
- **What a canvas re-encode does to the file.** `toBlob(callback, type, quality)`: "The default type is `image/png`; that type is also used if the given type isn't supported", and `quality` is "A Number between 0 and 1… A user agent will use its default quality value if this option is not specified" (VERIFIED [MDN](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob)). The page says nothing about metadata. A canvas is a bitmap, so the output has no EXIF: orientation, camera model and **GPS are gone** without any extra stripping step, and orientation must be applied while drawing (`createImageBitmap(file, { imageOrientation: 'from-image' })`, which is the documented default (VERIFIED [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/createImageBitmap))). A rejected `type` silently produces PNG, which for a photo is several times larger than the JPEG: check `blob.type` after encoding.
- **Quality.** One lossy generation at a quality the app picks (0.8–0.9) on a 2,048 px frame. This is the same class of loss as `auto=format` on the Sanity CDN, which `src/lib/sanity/client.ts` measured at 35–42 dB PSNR against a lossless rendition. The original is not kept unless the app also uploads it, and the map says photos only, uploaded from the phone, so the resized frame becomes the master.
- **Canvas size.** MDN: "iOS devices limit the canvas size to only 4,096 x 4,096 pixels… Exceeding the maximum dimensions or area renders the canvas unusable" (VERIFIED [MDN canvas](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/canvas), which links to an external test table for current values). A 12 MP iPhone frame is 4,032×3,024 and fits; 24 MP (5,712×4,284) and 48 MP (8,064×6,048) do not. `createImageBitmap` takes `resizeWidth`, `resizeHeight` and `resizeQuality` and accepts a `Blob` (VERIFIED, MDN), so the downscale can happen in the decoder before the canvas exists. MDN's compatibility table for the resize options did not render in the fetched page; Safari support for them is **unverified**.
- **HEIC.** Safari 17.0 "adds support for HEIC images" (VERIFIED [WebKit blog](https://webkit.org/blog/14445/webkit-features-in-safari-17-0/)); MDN's image-format page does not list HEIC at all, and Chrome and Firefox do not decode it (VERIFIED by absence on [MDN image types](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types)). What iOS hands a file input: WebKit's `WKFileUploadPanel.mm` asks PhotoKit for the "Compatible" representation unless the `accept` list includes the generic image type (`image/*` maps to `UTTypeImage`), in which case it asks for "Current"; camera captures without a file URL are re-encoded with `UIImageJPEGRepresentation(image, 0.8)` (VERIFIED [WebKit source](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/ios/forms/WKFileUploadPanel.mm)). What "Compatible" produces for a HEIC asset is PhotoKit behaviour that the WebKit file does not show: that it is a JPEG is an **inference** to confirm on a device. Android Chrome can pick a HEIC file it cannot decode, so the phone-side resize needs a fallback (refuse with a message, or upload the original for a server-side conversion).
- **Server-side conversion, if ever needed.** Sanity accepts `heif` but transforms only "JPEG, PNG, WebP, PJPG, TIFF, AVIF, and GIF" (VERIFIED [image-urls](https://www.sanity.io/docs/apis-and-sdks/image-urls)); Vercel Image Optimization optimizes only "image/jpeg, image/png, image/webp, image/avif. Other formats will be served as-is" (VERIFIED [image-optimization](https://vercel.com/docs/image-optimization)). Blob's `putImage()` converts at write time to jpeg, png, webp or avif and needs OIDC (VERIFIED); whether it reads HEIC is NOT FOUND. `sharp` is not a dependency today.

## Holes left open

- Whether a listener or Live Content connection is billed per connection, per event or per reconnect. Nothing on Sanity's pages says.
- The API CDN's invalidation delay after a mutation, and whether a private dataset is cached at all (two sentences on one page disagree; practice says cached).
- Cross-instance deduplication of a `'use cache: remote'` refill after `expire: 0`: Next's docs say revalidation is request-triggered and say nothing about concurrent requests on different instances.
- Whether iOS hands a JPEG for a HEIC asset in PhotoKit's "Compatible" mode: WebKit's source selects the mode; the conversion is PhotoKit's. Needs one device test.
- Safari support for `createImageBitmap`'s `resizeWidth`/`resizeHeight`; MDN's compatibility table did not render.
- The current iOS canvas limit: MDN's 4,096 figure is old and it defers to an external test page.
- Whether Blob's CDN varies its cache on a query string (which would let P4 bypass the 60 s floor).
- Which Growth document limit is right, 25k or 50k, and whether our Non-Profit variant follows the Growth overage rules (both carried over from #1416).
- Whether `putImage()` accepts HEIC input.
- No load test and no production write: production Sanity was read-only for this research, and no blob store was created.
